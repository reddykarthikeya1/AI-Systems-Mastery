# Debug Lab Incident Report: Tool Dispatcher Crashes the Agent Process on Bad Arguments and Hangs Forever on Slow Tools

- **Severity:** P1 Availability / Reliability
- **Affected Subsystem:** Module_03_Tool_Execution_and_Constrained_Generation
- **Reported Impact:** A single malformed tool call generated by the LLM (missing one argument) took down the entire agent worker process instead of being reported back to the model as a recoverable tool error. Separately, a tool call to a downstream API that stalled blocked the agent indefinitely with nothing to recover it.

---

## 🚨 Observable Symptoms & Logs
```text
dispatch('add', {'a': 5}) crashed instead of reporting a tool error: TypeError: <lambda>() missing 1 required positional argument: 'b'
dispatch('subtract', ...) crashed the whole process: KeyError: 'subtract'
dispatch('hang', {'seconds': 2}) blocked the caller for 2.0s with no timeout enforced
```
Calling `dispatch()` with a registered tool and fully correct arguments works exactly as expected -- nothing about the happy path looks suspicious. The moment the LLM's tool call is missing a required argument, or names a tool that was never registered, `dispatch()` raises a raw Python exception straight out of the process instead of returning any kind of structured error the agent loop could act on. A tool that simply takes a while to respond (here simulated with a 2-second sleep) blocks the caller for the tool's full duration; nothing about `dispatch()` limits how long it is allowed to wait.

---

## 🔬 How to Reproduce
1. Navigate to this module's debug lab:
   ```bash
   cd Module_03_Tool_Execution_and_Constrained_Generation/debug_lab
   ```
2. `broken_dispatcher.py` only defines `BrokenToolDispatcher`; it has no demo entry point of its own. Save the snippet below as `repro.py` in the same directory and run `python repro.py`:
   ```python
   import time
   from broken_dispatcher import BrokenToolDispatcher

   dispatcher = BrokenToolDispatcher()
   dispatcher.tools = {
       "add": lambda a, b: a + b,
       "hang": lambda seconds: time.sleep(seconds) or "done",
   }

   try:
       dispatcher.dispatch("add", {"a": 5})
   except TypeError as e:
       print(f"dispatch('add', {{'a': 5}}) crashed instead of reporting a tool error: {type(e).__name__}: {e}")

   try:
       dispatcher.dispatch("subtract", {"a": 5, "b": 2})
   except KeyError as e:
       print(f"dispatch('subtract', ...) crashed the whole process: {type(e).__name__}: {e}")

   start = time.time()
   dispatcher.dispatch("hang", {"seconds": 2})
   elapsed = time.time() - start
   print(f"dispatch('hang', {{'seconds': 2}}) blocked the caller for {elapsed:.1f}s with no timeout enforced")
   ```
3. Observe that both the missing-argument call and the unknown-tool-name call raise unhandled exceptions rather than returning an error the caller can recover from, and that the slow tool blocks for its entire duration with nothing cutting it off early.
